# Pux Notch Bar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A native macOS notch overlay (`Pux.app`) that renders the state of the Pux engine, plus the headless `pux serve` engine mode it talks to.

**Architecture:** `pux serve` (Node, this repo) is a supervisor that spawns one `pux serve-worker <path>` child per registered repo, so the existing cwd-bound engine code (`detectProviders`, `generateFailureContext`, providers) runs unchanged inside each worker. The supervisor multiplexes the workers' JSON-line events onto its stdout and routes JSON-line commands from stdin. `Pux.app` (Swift Package under `macos/`) spawns `pux serve`, feeds events into a pure state reducer, and draws a liquid notch window with SwiftUI.

**Tech Stack:** TypeScript / Node 22 / vitest (engine); Swift 5.9 toolchain, SwiftUI, AppKit, UserNotifications, macOS 14+ (app); Homebrew cask; GitHub Actions `macos-latest`.

**Spec:** `docs/superpowers/specs/2026-10-16-notch-bar-design.md`

## Global Constraints

- Node engine: `"type": "module"`, imports end in `.js`, tests are `src/**/*.test.ts` run by `vitest run`, `pnpm run typecheck` must stay clean.
- Nothing in `src/providers/`, `src/context/`, `src/agents/` changes behaviour; `serve` is a new consumer.
- Config lives in `~/.config/pux/config.json` via `configDir()`; tests set `PUX_CONFIG_DIR`.
- Swift: `// swift-tools-version: 5.9`, `platforms: [.macOS(.v14)]`, no Xcode project, no third-party packages. Only Command Line Tools are installed on the author's Mac: `swift build` works, XCTest and Swift Testing do not link, so Swift unit tests run as the executable target `PuxCoreCheck` (`swift run PuxCoreCheck`, exit code 1 on any failure).
- Bundle id `sh.pux.bar`, `LSUIElement = true`, ad-hoc signature (`codesign -s -`), app version equals `package.json` version.
- Panel: width 360pt, height 240pt; collapsed notch pill 160×30pt on screens without a notch; hover-leave grace 300ms; auto-drop and "passed" glow both last 5s; spring `response: 0.45, dampingFraction: 0.68`; Reduce Motion → 0.2s ease, no droplets.
- Protocol: one JSON object per line, UTF-8, `type` field discriminates. Field names below are exact and shared by `src/serve/protocol.ts` and `macos/Sources/PuxCore/Protocol.swift`.

## Review Focus

1. A registered repo whose directory was deleted: the supervisor must drop it and emit `error`, never crash. (Task 3 test.)
2. A worker that exits (gh removed, node crash): the supervisor restarts it once with the same path and emits `error`; the app must keep showing the other repos. (Task 4 test.)
3. A `failure` event for a repo that is not currently selected while the panel is pinned: selection must not jump. (Task 7 test.)
4. The engine binary is found but is an old version without the protocol: the real 0.1.5 has an older HTTP `serve` that stays running without speaking the protocol; the app's 10s hello timeout terminates it and reports offline after three attempts. (Task 8 test on the reducer's `engineExited` handling, by hand on the app.)
5. A failed pipeline that is re-run and passes: the repo's glow must turn green and its `failure` must clear so Fix is disabled. (Task 2 and Task 7 tests.)

- Produces (`worker.ts`):
  ```ts
  export type WorkerDeps = {
    root: string;                       // absolute repo path; process.cwd() already equals root when run as a child
    repository: string | null;
    providers: Provider[];
    emit: (event: ServeEvent) => void;
    head?: () => Promise<string | null>;   // default: git rev-parse HEAD in root
    branch?: () => Promise<string | null>; // default: git rev-parse --abbrev-ref HEAD in root
    generate?: typeof generateFailureContext;
    fix?: { readLatestFailure: typeof readLatestFailure; detectAgents: typeof detectAgents; runFix: typeof runFix };
    intervalFor?: (snapshots: ProviderSnapshot[]) => number;
    setTimeout?: typeof globalThis.setTimeout;
  };
  export type Worker = { start(): void; stop(): void; handle(command: ServeCommand): Promise<void>; tick(): Promise<void> };
  export function createWorker(deps: WorkerDeps): Worker;
  ```
  `tick()` is one poll: refresh HEAD, poll providers, emit `state` only when the JSON of the providers array or the commit changed since the last emit, then for the first `failed` pipeline not yet captured call `generate`, read `.ai-context/failure.md`, emit `failure` with `errorWindow` = text between the first `## Error` heading and the next `##` (trimmed, at most 40 lines), `failedStep` = the `## Error · ` heading suffix or null, `exitCode` parsed from the `- Exit code:` line or null. Consent runs once on `start()` exactly as WatchApp does: decision `false` → nothing; `true` or no pending entries → apply; otherwise emit `consent-needed`.

  ```ts
  export type WorkerHandle = { send(command: ServeCommand): void; kill(): void; onLine(cb: (line: string) => void): void; onExit(cb: (code: number | null, stderrTail: string) => void): void };
  export type SupervisorDeps = {
    spawnWorker: (root: string) => WorkerHandle;   // default: child_process.spawn(process.execPath, [cliPath, "serve-worker", root])
    write: (line: string) => void;                 // default: process.stdout.write
    exists: (path: string) => Promise<boolean>;    // default: fs access
    watchConfig: (cb: () => void) => () => void;   // default: fs.watch on configDir(), debounced 1s
    version: string;
  };
  export type Supervisor = { start(): Promise<void>; handleLine(line: string): Promise<void>; stop(): void; reload(): Promise<void> };
  export function createSupervisor(deps: SupervisorDeps): Supervisor;
  ```
  Behaviour: `start()` writes `hello`, calls `reload()`, subscribes to config changes. `reload()` lists repos, drops any whose path fails `exists` (emits `error { repo, message: "<path> no longer exists; removed from watch list" }` and calls `removeWatchedRepo`), spawns workers for new paths, kills workers for removed paths, writes `repos`. Worker lines are forwarded verbatim (workers already include `repo`). On worker exit: emit `error { repo, message: "engine worker exited (<code>): <stderrTail>" }`, restart once; a second exit within 60s leaves it stopped. Commands with `repo` route to that worker; `remove-repo` calls `removeWatchedRepo` then `reload()`; `shutdown` kills all and resolves `stop()`.
